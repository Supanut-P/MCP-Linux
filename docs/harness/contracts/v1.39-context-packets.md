# v1.39 task context packets

Prerequisite: v1.38 verification closed with independent QA and Ubuntu/package
evidence. Preserve existing dirty work and all accepted v1 interfaces.

## Scope

Add task-bound READ-only context collect/continue/resolve surfaces beside
`workspace_context`. Reuse its bounded discovery and ranking, and the existing
summary/diff helpers; do not reuse delivery assertions from another task.
Worker packets default to 32 KiB; QA packets to 64 KiB. Measure the complete
serialized result envelope, including metadata and mandatory safety text.
Insufficient budget returns a bounded error rather than cutting safety text.

Read exact source bytes through the registered workspace guard with bounded
file handles and strict UTF-8 decoding. Complete stable reads may report a
SHA256 source fingerprint. Oversized, binary, invalid UTF-8 or changing files
must be explicitly unavailable; no prefix hash can represent the full source.
Existing guards are not an OS sandbox against hostile concurrent mutation.

Opaque references and continuation tokens bind actor/session, task, workspace
root identity and expiry, with entry/byte quotas. Resolve/resume rereads sources;
changed, deleted, relocated or expired sources cannot be silently unchanged.
Recompute snippets from freshly observed text; omit stale discovery match text.
Commit delivery history only for content actually included in a fitted packet.
Keep case-distinct Linux paths distinct and omit cross-file deduplication.

SQLite durable workflow, skill provenance, model/provider readiness and QA
receipts remain later milestones. No execution, writes or authority grants.

## Implementation and verification

Installed acceptance found modern MCP adds server-identity `_meta` after the
registry returns. Replan this newly observed transport-envelope failure as a
bounded integration repair: explicitly include the same identity metadata in
the three additive packet tools and their size calculation. Existing v1 tools
retain their mapper behavior. Require exact delivered-byte equality through
registry, modern HTTP and installed STDIO, then rerun all Ubuntu/package gates
on a new source snapshot. The first accepted-source gate run remains retained;
it does not close installed acceptance.

Also reserve the complete required run-budget warning block before every fit
and recount the final packet JSON/text when the server appends it. Include a
threshold-crossing real HTTP regression. Byte bounds describe normalized
client tool results; modern protocol `resultType` and JSON-RPC framing are
outside the harness packet budget.

One bounded worker owns the additive FileService raw reader and regression
tests. A second owns the packet runtime and regression tests. Lead owns the
discovery projection, public tool/schema/wiring and documents. Write scopes
are disjoint; maximum four agents total, depth one, two Luna attempts each.
Independent Sol reviews specification then implementation quality.

Tests cover multibyte/escaped/oversized envelopes; CRLF/raw hash and edits beyond
snippets; oversized/invalid UTF-8 sources; pruned delivery; stale and missing
sources/root replacement; actor/session/task isolation; expiry, quotas,
cancellation and continuation progress. Preserve frozen v1 contract. Run full
source/Ubuntu/package gates and installed STDIO/HTTP acceptance before advancing
to v1.40. Keep failures and source-bound evidence; publication stays unapproved.

# v1.41 Codex selection, results and cancellation

Prerequisite v1.40 closed: 624 source files, 47 evidence hashes, Ubuntu/package
and installed transport gates approved independently. Source metadata remains
1.40 until implementation QA. Primary dirty work and all rollback evidence stay.

Extend existing codex_run with optional role/model/effort and codex_status with
optional selection for local capability preflight. Old calls retain invocation
and response shape; structured enhanced status is additive on codex_task_status.
No new orchestration framework or arbitrary flags/config/provider/sandbox inputs.
The v1 stable policy explicitly permits additive optional fields; review and
regenerate only the affected canonical input schemas, with legacy regression
evidence. Keep six Codex tools and existing opt-in advertisement/permissions.

Use deterministic documented Astra/Sol/Luna presets; explicit overrides never
silently substitute another model. Validate at application and adapter boundaries.
Help/exec help proves flag support only. Preflight separates local invocation
readiness from unknown authentication/entitlement/quota; native accepted requests
prove only their matching point-in-time selection. Do not inspect/export secrets.
Bound discovery output, deadlines and cancellation. No login/install/config changes.

Enhanced launches use JSONL and ephemeral sessions with fixed approval/sandbox
controls, MCP/plugins/hooks/apps/subagent integrations and notify disabled.
Role grants no permissions: native write mode requires independent WRITE and
EXECUTE authorization; QA/planner/default selected analysis uses read-only.
No weakening of managed policies or bypass flags. Verify effective controls before
native execution; unsupported safety controls fail closed. These controls are not
proof of an OS sandbox against external integrations or escaped descendants.

Parse concatenated owned stdout, never stderr, with bounded final text and actual
usage or null. Success requires complete supported terminal events plus zero
process exit and no log eviction/malformed/incomplete records. Failures, timeouts,
cancellation and termination_unverified remain distinct. Actor/session/workspace
task ownership protects result/status/stop. Legacy non-JSON runs remain available.

Fix Linux owned process-group cancellation: direct parent exit does not prove
descendants stopped; verify group liveness and escalate only the owned group.
Test parent-first exit, SIGTERM-ignoring descendants, missing/denied group probes,
unverified termination and repeat stop. Do not kill processes by name or claim
containment of descendants that detach into a new group.

Process repair uses bounded leader/survivor PID/start-time/group/session observations
and repeated nonexecution checks for zombies. This is an ordinary-process trust
boundary, with validation-to-signal and metadata snapshot races explicitly outside
OS containment claims. Aggregate sampling cost needs later load measurement.

Actual 0.146.0 effective config inspection found mcp_servers={} merges rather than
clearing configured entries. Enhanced launches must verify target-specific effective
inventory and explicitly disable each configured server before execution. Help
support is syntax readiness only. Enhanced launch now requires two target-specific
metadata probes with explicit verified controls. Independent implementation and
closure QA and package gates passed; see the
[closure receipt](../evidence/2026-10-03-v1.41-ubuntu.md). Preserve legacy calls.

Architecture correction after native evidence: app-server 0.146 rejects
`--ignore-user-config`, so an empty-home approximation cannot prove equivalence
with real-home execution. Probe and launch instead use the same sanitized runtime
environment, actual home, executable and workspace, with centralized role overrides.
No auth copying or global configuration writes. Layer changes invalidate preflight;
custom provider/endpoint configuration and expanded workspace-write roots/network/
temporary-directory access fail verification. A bounded inline TOML map explicitly
disables every inventoried server, including dotted IDs; an empty map never grants
readiness. Fixed controls are verified rather than inferred from CLI syntax.
The fingerprint binds observed layers, environment identity, cwd, executable, role
and overrides. No caching of successful preflight. File changes after the second
probe remain an ordinary filesystem TOCTOU boundary, not immutable OS containment.

Noninteractive managed commands receive stdin EOF; there is no interactive stdin
API. Unix group absence cannot establish Windows termination: unsupported native
group probes return unverified rather than success. Windows literal model acceptance
and Linux process-group cancellation are separate evidence boundaries.

One bounded fresh Luna worker owns selection/result helpers; one disjoint Luna
debugging worker owns process termination fixes. Lead owns adapter/discovery/
application/MCP integration and docs. Independent Sol QA; max four active agents,
depth one, at most two Luna attempts then one Sol repair. Preserve safety/context.

User explicitly chose the already authenticated Windows CLI for native tests
first. Windows native model acceptance is separate from Ubuntu/package evidence;
Linux VM currently has no Codex in PATH, and credentials are not copied. Do not
claim Linux native provider readiness. Complete local/native Windows evidence,

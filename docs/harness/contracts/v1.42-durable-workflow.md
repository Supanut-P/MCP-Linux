# v1.42 durable caller-native workflow state

Prerequisite: v1.41 verification closed under its Ubuntu closure receipt.
Keep metadata 1.41.0 until implementation QA. Preserve dirty primary work.

Use existing SQLite migrations/backups and caller-native execution. Add a bounded
immutable DAG of prepared task contracts, owner-scoped status, atomic task claims,
ordered events and reference-only checkpoints. Coordination never dispatches a
process, performs file edits, or converts caller evidence into verified QA.

Owner comes only from the server-configured stable actor clientId, never request
data or clientName. HTTP reconnect sessions can recover the same single-user actor
state; this is not team RBAC or proof that separate clients sharing that trusted
principal are different people. Revalidate registered workspace roots, immutable
allowed-file paths and current permission policy before mutations and resume.
READ protects inspection; WRITE protects durable metadata changes. Actual native
execution retains its independent EXECUTE/WRITE/confirmation policy.

Task states: planned, ready, running, verifying, done, blocked, failed, cancelled.
Start is an atomic metadata claim from ready with dependencies done, not execution
proof. Random claim tokens and revision comparison fence task updates. Claims
never expire or transfer automatically. Resume is inspection only: retain active
claims and uncertainty, completed work stays done, and dispatch remains false.
Cancelled work cannot restart; caller must reconcile external effects separately.
Result completion is explicitly caller-reported/unverified until v1.44 receipts.

Create DAG and every transition plus event in one BEGIN IMMEDIATE transaction.
Bound workflows/tasks/contract bytes/checkpoints/events, use paginated ordered
events and fail closed on quota/corrupt state. Checkpoints contain bounded summary
and references, no raw logs/secrets/process handles/executable continuations.
Additive tables are ignored by old binaries; rollback never consumes new tasks.
Do not claim file-scope collision protection (v1.43) or source-bound QA (v1.44).

Acceptance: real SQLite reopen after claim/checkpoint/done; two connections cannot
claim one task; dependencies/cycles/duplicate IDs denied; stale token/revision,
cross-owner and revoked-policy requests denied; aborted calls do not mutate;
events remain ordered and bounded; resume never dispatches. Full Ubuntu/package,
old-binary rollback, installed STDIO/HTTP recovery and independent QA must pass
before v1.43. Root state evidence links to immutable source and package hashes.

# v1.43 coordinated file scope and fenced leases

Prerequisite: v1.42 verification closed (660 source / 62 evidence hashes).
Keep metadata 1.42.0 until implementation QA. Preserve primary dirty work.

Extend the metadata-only workflow tool and SQLite repository; no new executor.
Default claims reserve the registered workspace; explicit disjoint mode reserves
the task's immutable literal file scopes. Canonical absolute identities cross
workflow, owner and overlapping registered-root boundaries. Resolve missing
components from a real existing ancestor; conservatively fold case and compare
path components. Detect or reject ambiguous hardlinked/changed identities.
Existing directories reserve descendants. Locks grant no filesystem authority.

Acquire all reservations plus claim/revision/event atomically. Bound lease TTL
and renewal; expiry or cancellation quarantines reservations rather than freeing
them. Expired fencing cannot checkpoint, renew or deliver a result. Never admit
a replacement writer automatically while previous execution may still run.
Explicit owner reconciliation requires current WRITE permission, confirmation
that the native writer has stopped and review of its effects; this is caller
evidence, not OS termination proof. Invalidate old claims before reuse.

Capture a bounded source baseline at claim, preserving existing dirty changes.
Before verifying/done, inspect source deltas including deletions/rename endpoints/
binary changes and nonignored untracked source. Reject outside-contract changes,
identity drift, truncation, unstable reads and stale handoff fingerprints. A done
transition must bind to the exact source checked for handoff. References and QA
remain caller-reported until v1.44. Ignored build output and escaped physical
writes are outside the diff boundary and must be named in receipts.

Use an additive migration and connection-only version guard triggers so v1.42
binaries may read migrated workflow metadata but cannot mutate coordination while
ignoring leases. Old v1 tools remain compatible; binary rollback does not consume
or restart new tasks. Active pre-lease tasks require reconciliation and block
overlap; do not assume restarting the MCP process terminated native workers.

Acceptance: coordinated worker two cannot claim an overlapping scope; explicit
disjoint claims succeed; nested roots/symlink/missing-file aliases collide;
cross-owner conflicts reveal no holder data; expiry/cancel/reopen retain quarantine;
stale tokens cannot submit newer results; source drift/out-of-scope/truncation fail
handoff; dirty baseline retained; old binary writes fail without new guard.
Use real SQLite and independent processes for contention proof. Full Ubuntu,
package lifecycle, installed STDIO/HTTP and independent QA precede v1.44.

This gate proves coordination admission and result fencing. Native callers can
still write physically; it does not implement an OS sandbox or trusted process
termination attestation. Keep one writer unless disjoint claims are verified.

Concurrent disjoint handoffs require explicit caller acknowledgement bound to
baseline/current source digests, claim token and task revision. Only changes
covered by overlapping reservation histories may be acknowledged; unreserved or
ambiguous changes fail. Preserve the original baseline and released intervals;
physical authorship remains unverified. No cross-owner paths appear in output.
Canonical allowed identities are frozen for workspace and disjoint modes;
atomic regular-file replacement is valid when the canonical path remains stable.
Two bounded content/inventory passes detect common races, with a disclosed
after-final-check TOCTOU boundary. Linux reads use nonblocking/no-follow open.

The first Ubuntu snapshot revealed a pre-existing native durable-shell startup
race: PID publication preceded identity publication, and reconciliation falsely
reported a still-live worker as exited. Repair the paired publication without
overwriting worker-owned task metadata; retain first-line PID compatibility and
report legacy unverified live processes conservatively. The initial snapshot and
failed logs remain retained. A fresh source export must pass the original full
gate plus deterministic startup-window regression before package acceptance.

The r2 run exposed a separate pre-existing validation defect: group member PID
strings beginning with 1 (for example 107215) were rejected despite being valid
process IDs. Replan this repair as a bounded numeric-validation change: accept
all safe integer PIDs greater than 1, reject zero, one, leading zeros and unsafe
integers, and preserve process identity checks before signaling. Require a
cross-platform red/green regression and a fresh immutable Ubuntu snapshot.

The r3 Ubuntu run passed all 14 durable-shell tests but exposed a test-harness
path defect: independent concurrency subprocesses assumed repository-root cwd,
whereas recursive pnpm tests run from each package. Resolve subprocess inputs
and cwd from the test module URL, verify from the storage package directory, and
retain the failed r3 gate. This test-only correction requires a fresh snapshot;
it does not weaken concurrency assertions or alter production admission logic.

# v1.45 usage reports and source-matched benchmark

Prerequisite: v1.44 verification is closed under its Ubuntu receipt. Preserve
dirty work and keep candidate metadata 1.44.0 until implementation QA.

Use a bounded local benchmark import/report CLI and a reusable TypeScript
reporting module. Do not add an executor, workflow state mutation, SQLite
migration, credentials, provider configuration or new orchestration framework.
The CLI reads explicitly named local evidence only and never executes commands.
Existing workflow exports must come from owner-scoped READ operations.

Freeze six fixtures: small edit, bugfix, refactor, context retrieval, incident
diagnosis and resume. Each single-agent/routed pair shares source fingerprint,
inputs, acceptance and safety criteria. Freeze every expected invocation in a
roster, including lead/planner/worker/QA and retries actually used. Small tasks
may route to lead only. Missing roster members, duplicate invocation identities
or mismatched source/acceptance hashes must not produce a comparable pair.

Record provider/model/effort, exact context-file bytes, raw log fingerprints,
outcome, retries, tool calls and elapsed time, with measurement provenance.
Provider input/cached/output usage comes from actual structured logs when
available. Total tokens equals input plus output; cached input is a subset and
must not be added again. Missing, failed, ambiguous or truncated usage must not
turn a known subtotal into a complete total. Unknown usage stays null, with
explicit coverage and reason codes. Never estimate tokens from context bytes.

Bound inputs, sources, logs, outputs and invocation counts. Reject malformed
fields, unsafe numbers/overflow, duplicate IDs, path escapes and ambiguous
evidence. Resolve local file references under an explicit evidence directory;
reject links and special files. No URLs, arbitrary module imports or shell
execution. Hashes prove byte integrity, not truth or physical authorship.
Acceptance/safety outcomes remain caller-attested unless separately checked by
retained deterministic checks. Reports do not grant workflow completion rights.

Keep all six pairs and all failures in success/safety comparisons. Evaluate the
experimental 25% median total-token reduction only when both variants have
complete actual telemetry for all fixtures, without success regression and
with zero safety failures. Otherwise report not_evaluable or the measured miss.
Context-file byte savings are separate from total provider context/token savings.

Verification: focused negative/accounting/pairing regressions; six real native
Windows CLI comparisons using the already authorized logged-in CLI and available
explicit model overrides, with every routed call retained; full local gates;
Ubuntu/package/installed report smoke and v1 compatibility before advancing.
Record unsupported default aliases instead of treating overrides as proof of
the default model. Native Linux provider readiness remains a separate v2 gate.
Fixture-only parser tests cannot close the actual model benchmark. If provider
access fails, retain the failed run and continue independent verification while
the benchmark comparison remains open. Publication requires human approval.

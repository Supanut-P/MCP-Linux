# v1.47 durable bounded incident observations

v1.46 Ubuntu verification is closed. Add `incident` with `collect`, `status`,
`report`, using registered workspaces and host IDs or an owned fleet selection.
Collection performs fixed read probes only; there is no scheduler, model dispatch,
mutation, replay or new SSH/filesystem authority. Follow the repo incident skill.

Use caller-known incident IDs and a canonical request fingerprint. Repeating an
identical collect returns existing state; a different request for that ID fails.
Persist `collecting` before probes, append evidence as it completes, then finalize
`complete`, `partial`, `unavailable` or `interrupted`. A 60-second lease/deadline
bounds all sources. Expired collecting records are projected interrupted, never
automatically executed. Fence evidence/finalization by run token and collecting
state; reject late results after terminal state/deadline. Preserve partial rows.

Selection is limited to 20 hosts and four simultaneous remote reads. Collect
health, validated service status, bounded journal metadata and registered-root
disk usage; add explicitly local runtime numeric metrics and bounded watcher
change metadata. Unit omission is an explicit gap for service/journal probes.
Every selected source receives an observation or explicit timeout/unavailable/
stale/truncated indication. Watcher changes are not deployment history.

Do not persist raw journal messages, provider errors, connection details,
secret references or credentials. Existing regex redaction is insufficient to
promise secret-free durable text. Store counts/status, allowlisted numeric
metrics, canonical times and hashes of watcher path references. Journal metadata
has `messageOmitted:true`; richer messages require a separately reviewed privacy
contract. No conclusion infers absence from an omitted or failed source.

Evidence has incident ID, sequence, content hash, source kind, host/workspace
reference, observation time, nullable provider time, status and truncation/gap
flags. Timeline orders observed times without inventing event timestamps.
Snapshot registration identity hashes and check before/after reads; changed
bindings invalidate usable observations. Reports retain historical rows and
separately indicate current binding drift. References resolve to bounded stored
rows; hashes prove retained bytes, not truth of provider claims.

Owner follows server actor ID hashing. CLI has a fixed principal; catalog and
incident ownership are not tenant authentication. Collect requires current READ
and WRITE for persistence; status/report READ. Recheck policy/cancellation after
asynchronous work. No saved approval grants subsequent execution.

Two additive SQLite tables: owner/ID header plus immutable evidence rows. Limits:
32 incidents per owner, 256 globally, 128 rows and 256 KiB evidence per incident;
header JSON 8 KiB, each evidence JSON 4 KiB. Enforce transactionally and bound
stored SQL fields before JavaScript materialization. No automatic deletion.
Report pages contain at most 16 evidence rows by default/32 maximum. Startup
uses existing transactional migration backups; older binaries ignore tables.

Verify owner/policy/confirmation, idempotency mismatch/no replay, partial hosts,
outer deadline, interruption/reopen/late-result fencing, stale registration,
corrupt rows/quotas, secret canaries and evidence hash/paging integrity. Full
local, Ubuntu/package and installed STDIO/HTTP collection/reopen/lifecycle gates
must close before v1.48. Live fixture reads are separate from provider mocks.

One worker writes storage only; Lead owns coordinator/tool integration, with
independent Sol QA. No overlapping writer scopes or new dependencies.

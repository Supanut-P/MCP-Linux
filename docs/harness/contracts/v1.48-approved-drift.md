# v1.48 approved baseline drift

v1.47 Ubuntu/package verification is closed. Add `drift` capture/approve/compare/
status without changing the frozen `remote_fleet_diff` schema or semantics.
Use fixed registered-host service-status/checksum reads; no raw configuration
content, generic commands, remote writes, model dispatch or automatic replay.

An immutable capture contains a registered workspace, at most 20 explicit targets
`{id,hostId,kind:service|config|artifact,unit|path}`, request hash, registration
fingerprints, observation times and projection version. Paths are user-supplied
target metadata, confined to registered roots; reports expose path fingerprints,
not raw paths. Existing remote checksum secret/regular-file/root guards remain
mandatory. Service projection keeps only stable allowlisted states, not PID.
Config/artifact checksums establish byte equality, not effective behavior.

Persist collecting before probes, append bounded immutable observations, then
finalize a source-bound snapshot hash. Four concurrent probes at most, one shared
60-second request deadline including registry reads. Repeating a snapshot ID with
the same request reads existing state; different inputs fail. Restart/expired
collecting projects interrupted, never replays. Fence late writes by token/state/
deadline. Preserve partial rows and explicit missing observations.

Approve requires current READ/WRITE, explicit `userConfirmed:true`, candidate ID
and exact snapshot hash, complete valid observations and unchanged registrations.
Persist immutable owner/time/hash approval. Confirmation is caller-attested, not
independent human authentication. Approval grants no remote execution/write
authority; it only selects comparison bytes. Never silently approve or rebaseline.

Compare requires approved baseline ID/hash and a new comparison ID. Targets are
derived solely from that baseline; target overrides fail. Preserve baseline/current
source statuses and reason flags. Per-target precedence: stale registration or
projection, unavailable/missing observation, truncated, then changed/unchanged
only for two complete valid values. Counts retain every state; incomplete evidence
cannot become unchanged. Reject malformed/hostile checksum or service output.

Storage owns separate additive tables and transactions, SQL-bounded fields before
JavaScript materialization, canonical JSON and hash validation, owner isolation,
32 snapshots per owner/256 globally, 20 rows per snapshot, 32 KiB header and 64 KiB
evidence total, 4 KiB per row. No automatic deletion. Older binaries ignore new
tables. Stored schemas, uniqueness, header/evidence/approval hashes and terminal
state consistency are revalidated before reporting or comparison.

Verification: approval/hash spoof, cross-owner and current policy, omitted/malformed
baseline/current, registration replacement, truncation/status precedence, cancelled
or hung reads, restart/no replay/late result fence, quota/corrupt rows, secret
canaries and frozen old-tool behavior. Full local, Ubuntu/package, installed
STDIO/HTTP/lifecycle and native connector acceptance must close before v1.49.

Use one storage writer, one projection writer and Lead integration, followed by
independent Sol QA. Workers cannot install dependencies or mutate environment,
shared schemas, lockfiles, generated catalog or version metadata concurrently.

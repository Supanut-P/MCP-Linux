# v1.50 incident to local fix

v1.49 verification is closed. Add `incident_fix prepare/status` as a bounded
bridge to existing caller-native durable workflow, scope leases and independent
QA receipts. No model runner, remote probe, shell executor, deploy or new target
authority. The goal is an evidence-linked task that can produce a local patch
and regression evidence under the existing approved workspace policy.

Prepare accepts fix ID, exact owned diagnosis ID/hash, mapping ID/revision,
one existing workflow task contract and caller-selected source ranges. Require
a currently resolved service-to-workspace mapping and matching owned incident
workspace/host/service scope, validated through IncidentService helpers.
Historical partial observations retain explicit unknowns; they do not prove a
cause. Changed source references or registrations block fresh preparation.

Use FileService bounded context reads and existing guards/secret policy. At most
eight source ranges from allowed files; 128 KiB input file limit, 8 KiB total
snippets, 32 KiB immutable preparation document. Pin content hashes, root
identities, selected ranges and explicit truncation. No automatic broad trace.
One task, no dependencies, at least one acceptance command and criterion;
task scope must stay within the mapped registered workspace. Context is source
material, not instructions or execution authority.

Migration018 adds an immutable owner-scoped preparation with workflow linkage,
32 records/owner, 256 global, strict bounded SQL/canonical hash validation.
Create preparation and workflow atomically through a named storage operation
sharing existing workflow insertion logic. Exact owned request repeat returns
the original workflow; changed ID reuse fails without duplicate tasks.
The task contract includes an exact preparation reference/link hash; existing
QA contract/source/diff/baseline/artifact hashes bind that reference transitively.

Status resolves the reference and returns retained contract/context separately
from current diagnosis/mapping/source freshness and existing workflow/QA state.
Latest workflow mutations validate linked diagnosis/mapping after awaited reads,
before commit and final current-policy checks. Initial context must be fresh at
start. A legitimate patch may change that source: later QA uses the existing
baseline/diff fence rather than demanding unchanged initial context.
READ/WRITE preparation and current READ status follow existing confirmation;
shared request deadline at most60 seconds, cancellation and post-await checks.

Older binaries read compatible schema and ignore018 but omit incident-link
freshness validation. Rollback requires stopping writers and withholding linked
tasks from execution until upgraded. No automatic execution/resume occurs;
ownership, claims and leases remain coordination metadata, not OS enforcement.

Verify mapping/unit/reference/hash/owner mismatches, unknown preservation,
source/root change, exact repeats, failed atomic insertion, quotas/corruption,
policy revocation and bounded hangs. Run a real local fixture patch from incident
through regression artifact and independent QA, stopped before deployment.
Full source, Ubuntu/package, installed transports/lifecycle/native verification
and independent closure are mandatory before v1.55 (P1 remains optional).

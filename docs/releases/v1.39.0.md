# v1.39.0 — task context packets

Status: implementation candidate; independent implementation review approved
with no material findings. Full Ubuntu/package/installed acceptance remains
open. The configured test VM still
runs accepted v1.38.0. Publication is unapproved.

Adds optional READ-only `workspace_context_packet`, `_continue` and `_resolve`
beside the existing context APIs. Packets reread bounded source bytes, report
complete stable source hashes, and distinguish unavailable or stale context.
Snippets use freshly observed source, not cached search match text.

Worker/QA defaults are 32/64 KiB of the serialized MCP tool result, including
the existing text/structured-content duplication and mandatory safety footer.
This is the normalized client tool result, including server identity metadata
and any run-budget warning. Protocol `resultType`, transport headers/JSON-RPC
framing, caller history and model reasoning are
outside that budget. Source content is untrusted and references confer no
permissions. The serving-lifetime store is process-local, capped at eight
actor/session entries; each runtime has its own task/reference/text quotas.
Restart may invalidate references; durable workflow recovery remains later.

The new bounded reader rejects nonregular sources without blocking on Linux
FIFOs, validates UTF-8, and checks file/root identity. These are point-in-time
checks under existing registered workspace guards, not an OS sandbox against
hostile filesystem mutation or arbitrary-secret detection.

See the [milestone contract](../harness/contracts/v1.39-context-packets.md).
Do not advance to v1.40 until all gates and independent closure review pass.

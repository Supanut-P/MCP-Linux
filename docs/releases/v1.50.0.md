# v1.50.0: Incident to local fix workflow

Implementation and Ubuntu/package/installed verification closed after independent QA. See the [receipt](../harness/evidence/2026-10-03-v1.50-ubuntu.md). No publication is approved.

The additive `incident_fix prepare/status` tool binds an owned immutable diagnosis,
a registered service mapping, bounded source snippets and one durable workflow.
Migration 018 atomically stores preparation and task state. Repeated preparation
does not create a second task. Current linkage is checked at writer admission and
QA handoff; artifacts and source are checked after awaited linkage reads before
a synchronous retained-state fence and the state mutation.

Execution stays in caller-native workflow. This tool does not launch a model,
run tests, edit code or deploy. Independent source-bound QA remains required.
Partial incident unknowns remain explicit. Older binaries omit linked-task
freshness checks: stop writers and withhold these tasks during rollback.

See the [contract](../harness/contracts/v1.50-incident-fix.md) and
[caller guide](../harness/INCIDENT_FIX.md). Final native provider readiness,
benchmark targets, real fleet usability and v2 acceptance remain separate gates.

# v2.0.0 compatible product candidate

Combines AI engineering workflow and Linux operations evidence in a headless
MCP/CLI product while preserving v1 client invocations. The prepared native
workflow provides task scope, role prompts, current context and reviewed skill
provenance. Durable coordination persists dependencies, claims, events and
checkpoints; source-bound QA and ownership/scope checks govern handoff.

Fleet grouping, incident timelines, approved drift comparisons and explicit
diagnosis link registered services to a bounded local fix task. A verified
native worker snapshot can be integrated after checking the original source,
then regression/independent QA complete the task before deployment.

See [native execution and measured routing](../harness/NATIVE_LINUX_ACCEPTANCE.md)
and the [acceptance map](../harness/V2_ACCEPTANCE_MAP.md). Coordination resume
does not resume a provider session or redispatch uncertain work. Skills and
locks do not grant authority or provide an OS sandbox. Native execution stays
opt-in with existing permission/confirmation gates and host sandbox policy.

The native benchmark did not meet the 25% token reduction objective. The final
paired run accepted 4/6 cases in each variant with no observed tool-policy
failure and increased median total tokens 114.85%. Keep small work with one
Lead and deterministic checks. Model availability is account-dependent;
tested 5.6 overrides worked and unavailable 6.1 returned an explicit error.
P1 diagnostics/rehearsal/recovery features remain backlog.

Candidate gates and independent closure are pending. Seven-day soak remains
waived. Owner usability acceptance and publication require a final human gate;
no production readiness or publication is claimed.
